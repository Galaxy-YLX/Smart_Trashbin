# 智能垃圾桶控制器技术文档

> 本文档基于 `main.py` 编写，描述基于 M5Stack Tab5 的智能垃圾桶控制系统。

---

## 1. 项目概述

本项目实现一个智能垃圾桶控制器，核心功能包括：

- **开盖 / 关盖**：通过步进电机在绝对位置模式下运动到预设位置。
- **压缩**：通过扭矩模式让电机持续下压，压缩桶内垃圾。
- **容量检测**：通过扭矩模式压紧垃圾，采集电机位置并换算为容量百分比。
- **距离检测**：通过 DTOF-2510 ToF 测距传感器实时测量桶内距离。
- **自动开盖**：当测距 ≤ 200 mm（20 cm）时自动触发开盖。

运行平台为 **M5Stack Tab5**，固件为 **UIFlow2.0（MicroPython）**，主控通过 **RS485 总线** 驱动一台 **正点原子 PD42S1 智能步进电机**（从机地址 `0x01`）。

RS485 接口与协议帧沿用同目录下的 `CPDR.py`（已在 Tab5 上验证）。本项目在其基础上新增：

| 能力 | 指令 | 说明 |
|------|------|------|
| 绝对位置模式 | `0xF2` | 开 / 关盖 |
| 扭矩模式 | `0xF0` | 压缩 / 容量检测 |
| 读取位置 | `0x2A` | 实时位置 |
| 读取堵转标志 | `0x2D` | 堵转状态 |
| 读取到位标志 | `0x30` | 到位状态 |

## 3. 软件架构

代码采用 **单线程 + 协作式状态机** 结构，由 `setup()` 完成初始化，`loop()` 循环轮询驱动：

```
setup()
  ├── UI 初始化（页面、标签、按钮）
  ├── RS485 初始化 + 电机使能 + 开启命令回显
  ├── 通信自检（读取一次位置）
  └── 红外传感器 UART 初始化（失败不阻塞）

loop() 每 10ms 执行一次：
  ├── M5.update()               UI 刷新
  ├── _feed_rx() / _proc_frames()   读取并解析电机应答
  ├── 待处理任务登记 → _begin_task()  执行用户按下的功能
  ├── _task_machine()           任务状态机推进
  └── _sensor_poll()            红外测距轮询
```

全局状态分为三组：

- `m`：电机状态（`pos` / `clog` / `arrived` / `last_rx`）。
- `g`：任务状态（`task` / `phase` / `hist` 采样窗口 / `pending` 待执行任务等）。
- `s`：传感器轮询计时。

## 4. RS485 通信协议

### 4.1 帧结构

**发送帧**（主机 → 电机）：

```
| C5 | addr | func | data... | checksum | 5C |
```

- `0xC5`：帧头
- `addr`：从机地址（本项目固定 `0x01`）
- `func`：功能码
- `data...`：参数字节
- `checksum`：校验和，为 `data` 前所有字节累加和的低 8 位
- `0x5C`：帧尾

**应答帧**（电机 → 主机）：

```
| C5 | addr | func | err | data... | checksum | 5C |
```

- `err`：`0x01` 表示成功，其他值表示错误。

### 4.2 功能码一览

| 功能码 | 常量 | 说明 | 帧长（发送） |
|--------|------|------|--------------|
| `0xF2` | `_F_POS` | 绝对位置模式运动 | 14 字节 |
| `0xF0` | `_F_TORQUE` | 扭矩模式运动 | 8 字节 |
| `0x64` | `_F_POS_TQ` | 设置位置环最大电流 | 7 字节 |
| `0xFA` | `_F_EN` | 电机使能（0=使能，1=失能） | 6 字节 |
| `0x6F` | `_F_ECHO` | 设置命令回显 | 6 字节 |
| `0xFC` | `_F_STOP` | 立即停止（抱闸） | 5 字节 |
| `0xFB` | `_F_CLEAR` | 清除状态（堵转/故障/抱闸） | 5 字节 |
| `0x2A` | `_F_RD_POS` | 读取实时位置 | 5 字节 |
| `0x2D` | `_F_RD_CLOG` | 读取堵转标志 | 5 字节 |
| `0x30` | `_F_RD_ARV` | 读取到位标志 | 5 字节 |

### 4.3 帧构建函数

| 函数 | 对应功能码 | 说明 |
|------|-----------|------|
| `_build_pos()` | `0xF2` | 绝对位置运动，参数含方向、加减速、速度、脉冲数 |
| `_build_torque()` | `0xF0` | 扭矩运动，参数含方向、电流 |
| `_build_read()` | 任意读指令 | 通用 5 字节读帧 |
| `_build_enable()` | `0xFA` | 使能/失能 |
| `_build_set_pos_torque()` | `0x64` | 设置位置环最大电流 |
| `_build_set_echo()` | `0x6F` | 设置命令回显 |
| `_build_stop()` | `0xFC` | 立即停止 |
| `_build_clear()` | `0xFB` | 清除状态 |

### 4.4 半双工收发时序

`_rs485_send()` 实现半双工发送：

1. `DIR=1`（切换为发送态）
2. 延时 200 µs（DE 建立时间）
3. 写入数据到 TX 缓冲
4. `flush()` 阻塞到最后一个字节上线（无 `flush` 时按波特率估算时长）
5. `DIR=0`（切回接收态）
6. 延时 `CMD_GAP_MS`（50 ms，命令间隔，来自 `CPDR.py` 的调优值）

> 关键点：必须及时释放总线（`DIR=0`），否则电机应答会与本机发送器冲突。

### 4.5 命令回显的特殊语义（重要）

`0x6F`（命令回显）在本电机单元上 **语义反转**（与 STM32 例程注释相反）：

- `data=0`：**开启** 回显（会应答）
- `data=1`：**关闭** 回显（静默）

且关闭状态 **掉电后仍保持**，因此每次上电都必须重新开启回显。`setup()` 中会执行：

```python
_rs485_send(_build_set_echo(ADDR, 0))  # data=0 开启回显
```

`COMM_TIMEOUT_MS` 通信看门狗依赖回显应答，回显未开启时该检查会误报。

## 5. 电机控制与运动模式

### 5.1 运动参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `SPEED` | `10` | 速度（RPM） |
| `ACC` | `150` | 加减速（0~200，0=无斜坡） |
| `POS_OPEN` | `37000` | 开盖绝对位置 |
| `POS_CLOSE` | `25000` | 关盖绝对位置 |
| `TORQUE_MA` | `600` | 压缩/检测扭矩（mA，0~3000） |
| `POS_TQ_MA` | `600` | 开/关盖位置环最大电流（100~3000 mA） |
| `POS_FULL` | `13000` | 100% 容量对应位置 |
| `POS_EMPTY` | `25000` | 0% 容量对应位置 |

方向常量（0=CW 顺时针，1=CCW 逆时针）：

| 常量 | 值 | 说明 |
|------|-----|------|
| `DIR_OPEN` | `0` | 开盖：CW |
| `DIR_CLOSE` | `0` | 关盖：CW |
| `DIR_COMPRESS` | `1` | 压缩/检测：CCW |

> 若运动方向与预期相反，翻转对应方向常量即可。

### 5.2 开 / 关盖（绝对位置模式）

发送流程：

1. `_build_clear()` 清除旧状态
2. `_build_set_pos_torque(ADDR, POS_TQ_MA)` 设置位置环最大电流
3. `_build_pos(ADDR, DIR, ACC, SPEED, POS)` 运动到目标位置

完成判定与容量检测使用相同的 **静止判断**：位置停止变化且在目标容差 `TARGET_TOL` 内。

### 5.3 压缩 / 容量检测（扭矩模式）

发送一次 `_build_torque(ADDR, DIR_COMPRESS, TORQUE_MA)`，电机持续下压，**不主动抱闸**，通过 Open/Close 指令退出。

## 6. 任务状态机

### 6.1 任务类型

| 任务 | 模式 | 行为 |
|------|------|------|
| `open` | 绝对位置 | 运动到 `POS_OPEN` |
| `close` | 绝对位置 | 运动到 `POS_CLOSE` |
| `compress` | 扭矩 | 持续下压，发送后立即结束任务 |
| `check` | 扭矩 | 采样位置，静止后计算容量 |

### 6.2 任务登记与执行

按钮回调 `_make_task_cb()` 只在 `g['task']` 和 `g['pending']` 均为 `None` 时登记任务名到 `g['pending']`，由 `loop()` 统一执行 `_begin_task()`，避免在 LVGL 事件回调中直接发指令。

### 6.3 静止判断算法

开/关盖与容量检测共用同一静止判定逻辑：

1. 每 `POLL_MS`（200 ms）读取一次位置，累积到 `g['hist']`。
2. 当样本数 ≥ `CHECK_SAMPLES`（5 个，即 1 秒观测窗口）时，取最近 5 个样本 `win`。
3. 若 `max(win) - min(win) <= CHECK_DELTA`（10 个脉冲），判定为 **静止**。

**开/关盖**：静止且 `abs(win[-1] - target) <= TARGET_TOL`（300 脉冲）→ 成功；静止但远离目标 → 判定为卡阻，调用 `_abort_task()`。

**容量检测**：静止后按当前位置换算容量百分比。

### 6.4 异常保护

| 保护机制 | 参数 | 触发后动作 |
|----------|------|-----------|
| 任务超时 | `TASK_TIMEOUT_MS` = 60 s | `_abort_task('timeout')` |
| 通信超时 | `COMM_TIMEOUT_MS` = 5 s | `_abort_task('motor no response...')` |
| 卡阻 | 静止但远离目标 | `_abort_task('stalled away from target')` |

`_abort_task()` 发送停止 + 清除指令，并将 UI 状态置为错误/占位符，然后清空任务。

## 7. 容量检测算法

容量通过电机当前位置换算：

```python
pct = (POS_EMPTY - pos) * 100 // (POS_EMPTY - POS_FULL)
pct = max(0, min(100, pct))
```

| 位置 | 容量 |
|------|------|
| `25000`（`POS_EMPTY`） | 0% |
| `13000`（`POS_FULL`） | 100% |

位置越低（越接近 `POS_FULL`）表示桶内垃圾越多、越满。检测时电机持续下压垃圾，静止位置越低容量越大。

## 8. 红外测距传感器

### 8.1 协议解析（DTOF-2510）

DTOF-2510 主动上报 **ASCII 文本行**，每条以换行 `\n` 结尾：

```
distance,confidence\n
```

- `distance`：距离（浮点，单位 **mm**），有效范围 20~10000 mm
- `confidence`：置信度/信噪比（整数，0~1000）
- 例：`123.4,88` 表示距离 123.4 mm、置信度 88
- 波特率 **921600**

### 8.2 解析器实现

`SensorParser` 类：

- `feed(data)` 累积字节流到 `self.buf`
- `parse()` 按 `\n` 切行，取逗号前的距离字段，四舍五入为整数 mm，越界（<20 或 >10000）则丢弃。

> 若使用其他传感器，只需修改 `SensorParser.parse()`。

### 8.3 轮询与容错

- 每 200 ms 轮询一次（`_sensor_poll`）。
- 每轮排空所有完整帧，取最新一帧距离显示（避免缓冲区累积）。
- 传感器 UART 初始化失败仅打印日志并置 `_sensor = None`，**不会阻塞主程序**。

### 8.4 自动开盖

当测距值 ≤ `AUTO_OPEN_MM`（默认 200 mm，即 20 cm）时自动触发开盖。采用下降沿触发（`s['near']` 标志），避免物体停留在范围内时重复触发；仅当无任务运行（`g['task']` 与 `g['pending']` 均为 `None`）时才会触发。

## 11. 关键实现细节与注意事项

1. **纯 ASCII 编码**：`main.py` 必须保持纯 ASCII，UIFlow2 网页编辑器在粘贴非 ASCII 字符时可能损坏代码。所有行宽 ≤ 72 字符，避免编辑器折行破坏代码。

2. **命令回显反转语义**：`0x6F` 的 `data=0` 为开启回显，`data=1` 为关闭；关闭状态掉电保持，必须每次上电重开。

3. **MicroPython `bytearray` 无切片删除**：`_next_frame()` 中通过重新赋值（`_rxbuf = _rxbuf[i:]`）实现缓冲裁剪。

4. **半双工总线释放**：发送后必须及时将 DIR 切回接收态，否则应答帧会与发送器冲突。

5. **位置有符号解析**：位置数据为 4 字节大端，`_proc_frames()` 中按有符号 int32 处理（≥ `0x80000000` 时减去 `0x100000000`）。

6. **传感器失败不阻塞**：红外传感器初始化异常只降级（置 `None`），不影响电机控制。

7. **压缩/检测不抱闸**：扭矩模式下电机持续下压，靠 Open/Close 指令退出，正常流程不会触发 `_abort_task()` 的抱闸。

## 12. 运行与使用

### 12.1 部署

将整个 `main.py` 复制到 UIFlow2 的 Python 模式运行。

### 12.2 上电流程

1. 初始化 UI 页面。
2. 初始化 RS485 并 **使能电机**（`_build_enable(ADDR, 0)`）。
3. **开启命令回显**（`_build_set_echo(ADDR, 0)`）。
4. 通信自检：读一次位置，500 ms 内收到应答则打印 `motor comm OK`，否则打印 `motor comm FAILED`。
5. 初始化红外传感器 UART（失败不阻塞）。
6. 打印就绪信息，进入 `loop()` 循环。

### 12.3 操作流程

| 操作 | 结果 |
|------|------|
| 按 **Open** | 开盖，盖子状态显示 `Opening... → Opened` |
| 按 **Close** | 关盖，盖子状态显示 `Closing... → Closed` |
| 按 **Compress** | 持续下压压缩垃圾 |
| 按 **Check** | 压紧后静止，容量显示百分比 |

## 13. 与 CPDR.py 的关系

本项目 RS485 接口、半双工收发、校验和、命令间隔等底层实现沿用 `CPDR.py`（已验证）。差异如下：

| 维度 | CPDR.py | main.py |
|------|---------|---------|
| 电机数量 | 2（双电机 CoreXY） | 1 |
| 运动模式 | 相对位置 `0xF3` | 绝对位置 `0xF2` + 扭矩 `0xF0` |
| 位置模式 | 相对位置 | 绝对位置 |
| 读指令 | 无 | `0x2A` / `0x2D` / `0x30` |
| 任务状态机 | 无（同步移动） | 有（异步任务 + 静止判断） |
| 传感器 | 无 | 红外测距 |
| 通信看门狗 | 无 | 有（`COMM_TIMEOUT_MS`） |
